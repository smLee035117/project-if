## 1. 제품 정의 및 목표

Project IF는 사용자가 가상의 재난·생존 상황을 읽고 행동을 선택하면, **누적된 세계 상태·플레이어 상태·획득 정보·게임 내 경과 시간**에 따라 결과가 달라지는 단독 플레이 인터랙티브 시나리오 서비스다. 단순한 정답/오답 퀴즈가 아니라 그럴듯한 대안 사이에서 판단하고 행동의 인과관계를 경험하게 한다. 공개 화면은 ‘학습’보다는 선택·체험·발견을 중심으로 표현한다.

**V2 콘텐츠 범위.** 최초 공개 대상은 퇴근하겠습니다(`office_fire_01`)다. 아파트 화재, 정전, 산악 조난, 지하 침수는 비공개로 유지한다. 후속 시나리오는 독립된 시작·진행·결말 경로를 검증한 뒤 공개한다.

**최초 공개 범위에서 제외:** 자유 입력형 TRPG, 주사위/전투, NPC 자율 행동, 다중 플레이, 사용자 제작 도구, 회원가입·랭킹·광고·미션 보상·타 이용자 선택 비율 통계. 초기 기획의 ‘가이드 제작 도구’는 장기 확장 아이디어로 보존하되 현재 V2 완료 조건에 넣지 않는다.

### 1.1 기본 사용자 여정

1. 접속 → 공개 시나리오 목록에서 한 작품 선택
2. 회원가입 없이 게스트로 시작 → 초기 상황·실행 가능한 행동 확인
3. 행동 선택 → 결과 메시지·획득한 정보·갱신된 상황 확인
4. 시간·자원·위치·사건 변화에 따라 새로운 행동을 선택하며 반복
5. 사건의 인과관계에 따른 성공/실패 엔딩 확인 → 엔딩 크레딧에서 전체 행동 이력과 주요 판단·근거·출처 회고
6. 유효한 게스트 세션(7일)과 진행 중 플레이(마지막 행동 후 1시간)가 있으면 이어하기 또는 새로 시작하기를 선택

## 3. 기능 요구사항

각 요구사항은 **‘사용자/서비스 동작 → 서버 보장 → 완료 조건(AC)’** 순서로 기술한다. 기술 구현 상세나 파일명은 구현 대조표로 분리한다.

### F01. 서비스 진입 및 시나리오 선택

**F01-01 [확정] 공개 시나리오 목록**  
사용자는 제공 중인 작품의 이름을 확인하고 시작할 작품을 고를 수 있어야 한다.
**AC:** (1) 공개된 작품만 목록에 표시 (2) 미등록 ID 시작 시 명확한 오류 (3) 개별 시나리오가 독립적으로 실행 가능.

**F01-02 [확정] 시나리오 시작 화면**  
사용자는 첫 장면의 설명과 현재 가능한 행동을 확인한다.  
**AC:** (1) 사용자의 선택 이전에 숨겨진 사건 진상·미래 결과를 노출하지 않음 (2) 첫 장면이 유효한 행동 또는 명시적 결말을 갖도록 콘텐츠 검증.

### F02. 게스트 인증과 수명

**F02-01 [확정] 회원가입 없는 게스트 식별**  
서버는 게스트를 식별하고 토큰 원문 대신 서버 쪽 해시를 이용해 세션을 확인한다.  
**AC:** 새 게스트 발급, 유효한 세션 재사용, 비정상 토큰 거절, 타인 플레이 접근 불가.

**F02-02 [확정 · D-01·D-02·D-05] 게스트 인증·플레이 만료 정책**  
게스트 인증 쿠키와 MySQL 세션의 유효기간은 **발급 후 7일**이며, 플레이 진행 Redis 데이터는 **마지막으로 성공한 행동 이후 1시간**까지 유지한다. 새 플레이 생성 시 TTL은 3600초이고, 행동과 포기의 Redis 변경 성공 시 재설정한다. GET 조회·화면 유지로 연장하지 않는다. 별도의 `EXPIRED` 상태를 사용하지 않고 Redis 만료 후 유효한 게스트의 조회는 404로 응답한다. 세션 만료·인증 누락은 인증 오류로 별도 구분한다.
**AC:** (1) 쿠키·DB 7일 일치 (2) GET 시 TTL 불변 (3) 성공 행동 시 3600초 갱신 (4) 만료된 플레이는 404 (5) 인증 만료와 플레이 만료를 구분하고 진행이 종료된 플레이의 영속 결과는 Redis TTL과 분리.

**F02-03 [확정] 플레이 소유권 보호**  
조회·행동·종료 요청마다 실제 게스트 소유자인지 검사한다.  
**AC:** `playId`를 안다고 타인의 플레이를 조회하거나 변경할 수 없음. 클라이언트가 보낸 userId·점수·상태를 신뢰하지 않음.

### F03. 플레이 생명주기

**F03-01 [확정] 새 플레이 생성**  
등록된 시나리오를 선택하면 시나리오 버전·초기 세계 상태·초기 장면·시작 시간 등이 정해진 독립 플레이를 생성한다.  
**AC:** 서로 다른 플레이는 상태 객체를 공유하지 않음; 발급한 `playId`로 조회 가능; 시나리오의 버전과 초기 세계선을 시작 후 임의로 변경하지 않음.

**F03-02 [동결 · D-03] 게스트·시나리오별 이어하기**
게스트의 활성 플레이는 시나리오별 하나로 관리한다. 유효한 활성 플레이가 있으면 프론트엔드에서 이어하기와 새로 시작하기를 제공한다. 같은 시나리오에서 새로 시작할 때는 사용자가 포기를 확인하고 기존 플레이 포기가 반영된 뒤 생성한다. 다른 시나리오의 플레이는 독립적으로 유지할 수 있다.
**AC** (1) 쿠키와 시나리오 ID로 활성 조회 (2) 같은 조합에서 중복 시작 거절 (3) 포기 후 재생성 (4) 포기된 플레이에 추가 행동 거절.

**F03-03 [확정 · D-04] 명시적 포기**  
사용자가 명시적으로 포기할 수 있어야 한다. 이 경우 Redis 플레이를 `GIVEN_UP`으로 종료하고 추가 행동을 거부한다. 포기 결과는 MySQL 완료 로그에 저장하지 않는다. 브라우저 종료, TTL 만료, 포기 요청 없이 다른 시나리오를 시작한 경우를 포기로 집계하지 않는다.
**AC:** (1) V2 포기 API 제공 (2) 성공·실패 결과를 포기로 변경할 수 없음 (3) 포기 후 추가 행동 불가 (4) MySQL에 포기 기록 미저장 (5) 동시 요청 경합 안전성 검증.

**F03-04 [확정] 완료 후 추가 행동 거절**  
`CLEARED` 또는 `FAILED` 등 종료 상태에서는 새로운 행동으로 상태를 다시 변경하지 않는다.  
**AC:** 추가 행동이 성공으로 처리되지 않고 기존 종료 기록 유지.

### F04. 시나리오 규칙과 행동

**F04-01 [확정] 장면·행동 모델**  
각 작품은 장면별 설명과 행동을 제공한다. 행동은 같은 장면에 머무르거나 다른 장면으로 이동하거나 끝날 수 있다.  
**AC:** `STAY`, `GOTO(sceneId)`, `END(endingId)`가 공통 엔진에서 동작하며 20단계·2개 선택지를 강제하지 않음.

**F04-02 [확정] 상태 기반 행동 유효성**  
행동은 현재 위치·자원·획득 정보·조건을 기준으로 실행 가능 여부를 판단한다.  
**AC:** 실행 불가능한 요청은 상태를 변경하지 않고 거절; 플레이어에게는 비공개 `world` 값이 드러나지 않도록 표시 정책을 적용.

**F04-03 [확정] 같은 행동의 상태별 결과 분기**  
같은 행동이라도 누적 상태·시간·세계선에 따라 다른 결과가 발생할 수 있다.  
**AC:** 행동 후 적용 시점의 상태로 결과 조건을 검사하며, 일치하는 결과가 **정확히 하나**일 때만 상태를 갱신한다. 0개/복수 일치는 데이터 오류로 처리.

**F04-04 [확정] 상태 효과 계산**  
시나리오는 선언형 효과를 이용해 플레이어/세계 상태 또는 획득 정보를 바꾼다.  
**AC:** `SET`, `ADD`, `APPEND_UNIQUE`, `REMOVE` 지원; 자료형·경로 검사; 하나의 행동에서 일부 효과만 반영되는 상황 방지. **`ADD`의 음수 입력 자체는 허용**하고, 결과가 규칙상 허용되지 않는 값이 되는 것을 거절한다 [계약 후보].

**F04-05 [확정] 장면 위치의 일관성**  
장면 이동 시 현재 장면과 플레이어 위치가 서로 모순되어서는 안 된다.  
**AC:** RC2 계약에 따라 `GOTO` 성공 시 목적지 장면의 `location`으로 위치를 갱신하며, 이동할 때 같은 위치를 JSON 효과에서 중복 설정하지 않음 [계약 후보].

**F04-06 [확정] 행동 기반 가상 시간**  
게임 속 시간은 실제 브라우저 시간이 아니라 선택한 행동·대기 행동의 `durationMinutes`에 따라 전진한다.  
**AC:** 사용자가 아무 행동도 하지 않으면 게임 속 시간은 흐르지 않음; 경과 시간이 음수나 비정상 숫자가 되지 않음.

**F04-07 [확정·계약 후보] 시간 사건 처리**  
세계의 절대 시점 이벤트 및 조건 충족 뒤 일정 시간이 지나 발생하는 상대 이벤트가 행동 결과에 영향을 준다.  
**AC:** 사건 중복 발생 방지, 예약 시점 보존, 기준 시점 순서 적용, 행동 종료 경계에서 사건 반영 후 결과 판정. 장시간 이동은 여러 짧은 행동으로 분할; 현실에서 정확한 구조 도착 시간을 예측하는 기능으로 표현하지 않음.

**F04-08 [확정] 상태와 지식 분리**  
`world`는 객관적 비공개 사실, `player`는 위치·자원·행동 상태, `knowledge`는 획득한 사실을 나타낸다.  
**AC:** 공개 API에 원시 `world`를 포함하지 않음; 결과·행동 가능 여부를 통해 숨겨진 사실을 부당하게 누설하지 않음.

**F04-09 [확정] 결정론·조건/효과 안전성**  
JSON이 임의 JS나 `eval`을 실행하지 않으며 공통 엔진에서 선언된 규칙만 수행한다.  
**AC:** 누락 경로·잘못된 타입·잘못된 이동 참조·결과 조건 충돌을 검출하고 저장 전 거절.

### F05. 종료, 결과, 설명

**F05-01 [확정] 상태에 근거한 엔딩**  
결말은 마지막 단계 번호나 점수 하나로 결정하지 않고 누적 상태와 엔딩 조건으로 판정한다. 성공은 `CLEARED`, 사망·대피 실패·구조 실패 등 실패는 `FAILED`로 표현할 수 있다.  
**AC:** 효과를 반영한 뒤 엔딩 요구조건 확인; 불충족 시 상태·시간·버전 변경 없이 실패; 종료 이후 행동 불가.

**F05-02 [확정] 기술적 교착 금지**  
플레이가 `PLAYING`인데 실행 가능한 행동도 결말도 없는 상태가 되어서는 안 된다. `FAILED` 엔딩 자체는 버그가 아니다.  
**AC:** 대표 경로·경계 상태 탐색에서 교착을 검출하고 실패 종료/반복 루프의 도달 가능성을 별도 검증.

**F05-03 [확정 · D-06] 행동 직후 결과**  
사용자는 자신의 행동으로 즉시 무엇이 일어났는지를 확인한다. 아직 획득하지 않은 정보나 장래의 정답을 노출하지 않는다.  
**AC:** 결과 문구와 갱신된 공개 장면 표시; 다른 결과의 조건·비공개 정보는 응답에서 제외.

**F05-04 [제품 목표 · D-06·D-07] 엔딩 크레딧과 행동별 회고**
종료 후에는 **도달한 엔딩, 실제 수행한 전체 행동 타임라인, 중요 판단의 당시 정보·결과·근거, 참고 출처**를 엔딩 크레딧처럼 제공한다. 모든 행동에 정답/오답·점수·감점을 강제하지 않으며, 당시 알 수 없던 사후 정보를 근거로 잘못된 판단이라고 단정하지 않는다. 공식 지침과 창작 가정을 구분한다. 타 이용자의 선택 비율은 실제 이용자가 생긴 후 추가하는 후속 기능으로 분리한다.  
**AC:** (1) 성공·실패 엔딩 표시 (2) 전체 행동 순서 재구성 가능 (3) 핵심 판단의 맥락·근거를 표시 (4) 숨겨진 미래 결과·내부 상태를 진행 중에 노출하지 않음 (5) 결과 화면은 건너뛰거나 스크롤할 수 있음 (6) 선택 비율 집계는 후속 기능이다. 현재 HTTP는 엔딩과 행동 이력을 제공하며 행동별 판단 근거·출처 필드는 보류한다.

**F05-05 [확정 · D-10] 리뷰용 행동 이력 기록**  
진행 중 행동을 Redis 플레이 상태에 누적하고, `CLEARED` 또는 `FAILED`로 종료하면 결과와 함께 MySQL에 행동 이력을 영속화한다. `GIVEN_UP` 또는 비활동 만료 시 행동 이력을 MySQL에 저장하지 않는다. 시나리오 버전 변경 후에도 과거 플레이의 선택·결과를 재구성할 수 있게 **장면·행동·순서·가상 시각·당시 결과 문구**를 충분히 보존하되, 비공개 세계 상태 전체를 무조건 복사하지 않는다.
**AC:** (1) CAS 성공 행동만 이력에 남음 (2) 종료 결과와 이력 저장이 멱등적이고 복구 가능 (3) 저장 실패 시 Pending 보존 (4) 중복·동시 행동으로 중복 이력 발생하지 않음 (5) 기록된 행동·결과 문구는 MySQL에 보존. 콘텐츠 버전 교체 후 기존 플레이의 공개 조회 유지와 영속 결과 조회는 보류한다. MySQL 기록 보관·삭제 기간은 별도 운영 정책으로 결정한다.

### F06. 데이터 일관성과 복구

**F06-01 [확정] 동일 플레이 동시 갱신 보호**  
동일 버전을 기반으로 여러 행동이 경합하면 하나만 상태 갱신에 성공한다.  
**AC:** 검사와 저장이 원자적으로 이루어지고 실패한 요청이 다른 요청의 결과를 덮어쓰지 않음.

**F06-02 [동결] 응답 유실과 재전송 처리**
동일 버전의 행동 재전송은 버전 검증으로 중복 반영을 막는다. 응답 유실이나 서버 오류 후 화면은 현재 상태를 재조회한다. 기존 성공 응답을 재생하는 `requestId` 계약은 후속 범위다.

**F06-03 [확정 · D-10] 완료 결과와 행동 이력의 멱등 영속 저장**  
`CLEARED`·`FAILED`로 종료된 플레이는 최종 결과, 엔딩, 진행 메타데이터, 행동 이력을 MySQL에 저장한다. `GIVEN_UP`과 TTL 만료는 MySQL 완료 결과로 저장하지 않는다.  
**AC:** (1) `playId` 기준 동일 결과 및 이력의 중복 저장 안전 (2) 같은 내용의 재저장 허용 (3) 이력이 다르거나 결과가 다른 중복 요청은 불일치 거절 (4) MySQL 실패 후 Pending을 통해 모두 재처리 가능.

**F06-04 [확정] 부분 장애 복구**  
Redis 종료 저장에 성공하고 MySQL 결과 저장에 실패한 경우에도 재처리할 수 있어야 한다.  
**AC:** 종료 상태와 pending 결과의 원자 기록; MySQL 저장 성공 후 pending 제거; 실패 시 보존; 부팅 및 정기 복구 재시도; 재시도 중복 방지.

### F07. 시나리오 콘텐츠와 버전

**F07-01 [확정] 외부 JSON 콘텐츠 로딩·검증**  
등록된 시나리오 JSON은 공통 로더에서 검증된다. 아파트 화재 시작 시 초기 세계선 추첨이 적용된다.
**AC:** 장면/행동 ID, 참조, 조건·효과 타입, 엔딩, 이벤트, 공개 데이터 경계 검증.

**F07-02 [확정] 버전 및 초기 세계선**  
시작한 플레이의 시나리오 버전과 선택된 초기 세계선은 진행 중 고정한다.  
**AC:** 콘텐츠 업데이트로 진행 중인 플레이의 규칙이 조용히 바뀌지 않음; 화재의 X/Y/Z 등 초기 변형을 콘텐츠가 표현 가능 [초기 변형 상세는 계약 후보].

**F07-03 [동결 · D-08·D-09] 최초 공개와 후속 콘텐츠**
최초 공개 등록 범위는 `office_fire_01` 한 작품이다. 이 작품의 대표 경로를 실제 JSON과 NestJS·Redis·MySQL을 연결한 테스트에서 검증한다. 나머지 작품은 경로, 엔딩, 콘텐츠 품질을 각각 검증한 뒤 공개한다.

### F08. 웹서비스 공개 및 운영

**F08-01 [확정 목표] 최소 웹 UI**  
시나리오 목록, 현재 장면, 행동 버튼, 행동 결과, 종료 화면을 이용할 수 있어야 한다.  
**AC:** 실제 API와 연결되고 이어하기/새로 시작하기 확인, 포기, 엔딩 크레딧이 작동하며 세션·오류·중복 클릭·충돌·만료 상황에서 오해를 유발하지 않음.

**F08-02 [확정 목표] 자동 테스트와 재현 가능한 실행**  
백엔드는 자동 테스트로 주요 성공·실패·경쟁 상태를 검증하고 타 환경에서 구동 가능해야 한다.  
**AC:** 단위·HTTP·Redis/MySQL 통합 테스트, 빌드, 설정 예시, Docker 기반 실행, CI 실행 절차 제공.

**F08-03 [확정 목표] 배포·최소 운영 안전장치**  
외부 접속 가능한 서비스를 배포하며 운영 중 문제를 진단할 수 있어야 한다.  
**AC:** 비밀정보 분리, 요청 추적 로그(민감정보 제외), 헬스 체크, 장애 확인 및 복구 절차, 공개 플레이 검증.

| ID | 현재 범위 |
|---|---|

| D-02 | Redis 생성·변경 성공 시 3600초, 조회 시 유지 |
| D-03 | 게스트·시나리오별 활성 슬롯, 포기 요청을 거쳐 재시작 |

| D-06 | 행동 직후 문구와 종료 이력 제공, 판단 근거·출처를 포함하는 회고는 제품 목표 |
| D-07 | V2 공개 API는 상태와 엔딩 중심 |
| D-08 | 최초 공개 콘텐츠의 통합 경로를 검증하고 백엔드 연동 계약 동결. 후속 작품은 개별 검증 |
| D-09 | `office_fire_01`만 공개 등록. 사용자 웹·공개 배포는 남음 |
| D-10 | 성공·실패 결과와 행동 이력 MySQL 보존. 포기·만료 제외 |

**최초 공개 이후 검토:** 회원가입, 기기 간 기록 복원, 발견 엔딩 수집, 타 이용자의 선택 비율 통계. 선택 비율의 통계 정의·수집 방식은 기능을 도입하는 시점에 설계한다.

**별도 운영 정책 필요:** MySQL에 저장한 익명 완료 기록의 보관·삭제 기간, Redis 영속성·백업, 배포 보안·로그 정책. 이 항목을 D-01~D-10의 제품 결정 완료와 혼동하지 않는다.

## 5. V2.0 범위에서 의도적으로 제외하거나 보류한 사항

- V1의 단계별 2지선다·20스테이지·모든 행동에 GOOD/BAD 등급 강제
- 자유 텍스트 행동 입력, TRPG 전투·주사위·자율 NPC, 다중 사용자 실시간 협업
- 사용자 제작 시나리오 편집기/공유·투고 시스템(장기 비전)
- 회원가입·계정 이전, 발견 엔딩 수집, 다른 이용자의 선택 비율 통계, 랭킹·광고·미션 보상·수익화(후순위)
- 중첩 OR/NOT 조건 AST 및 실제 물리 시뮬레이션(현재 4종에 필수 아님)
- 별도의 대규모 부하 테스트 프로젝트(핵심 서비스 완성 이후 추가 가능)

## 6. 완료 판단 원칙

- **코드가 있다** ≠ **기능이 완료되었다**. 유효한 JSON·API·실제 화면·예외 경로가 함께 연결되어야 사용자 기능이 완성된다.
- 핵심 불변식: 타인 플레이 접근 금지 / 숨겨진 world 정보 보호 / 동일 버전 중복 반영 방지 / 종료 후 변경 방지 / 저장 실패 후 복구 가능 / 플레이 교착 금지.
- 백엔드 동결 검증은 최초 공개 작품의 통합 테스트와 공개 API 계약을 기준으로 한다. 후속 작품은 공개 전 독립적으로 검증한다.
- 재난 관련 현실 행동 지침은 실제 출처와 창작 시뮬레이션 요소를 구분하고, 공개 전 필요 수준의 안전성 검토를 수행한다.
